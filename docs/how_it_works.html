What happens when you press Solve

Everything you set up before a run is a case: cases/<case>/case.json plus its mesh in cases/<case>/mesh/. The app never runs physics itself. Solve starts python run.py --case cases/<case> --name <run> as a separate process, and that process does everything below, writing the result into cases/<case>/results/<run>/. Older runs made from the command line (run.py <template> --set …) live in results/<run>/ and still open read-only.

Inside one run folder

A result: the real contents of the narrow-pore charging run (97 MB), plus the three files every case run adds (case.json, convergence.txt, mesh/case.msh). For a case run the folder is cases/<case>/results/<run>/. Pick a file to see what it holds, who writes it, when, and who reads it.

Where the mesh is

Each case owns one mesh: cases/<case>/mesh/case.msh (P2, named boundaries), created by Create mesh (Geometry or Mesh step; runs on the CPU) or by the first Solve, then reused by every run until a geometry, mesh or materials setting changes. During a run it lives in memory as a Mesh object (pnpflow/mesh.py); each result keeps a copy, its pictures and its Mesh Validation.

Which .msh to use.

mesh/case.msh keeps the named physical groups and is the one to reuse (geometry.load_msh). solution.msh is written through meshio with every element in physical group 1, so the boundary names are lost there; it is only for looking at the fields in gmsh. Runs made from the command line without a case (results/<run>/) do not save a mesh at all, only solution.*.

How the app and the solver talk

Everything goes through files on disk, so a run started from the terminal shows up in the app the same way as one started from the Solve button.

App (browser)

app/ui/: plain JS modules, WebGL field view, Plotly charts. Opens at http://localhost:8766.

  • Template list and defaults from /api/cases (= run.py --list)
  • Parameter edits stay in the browser until Solve (they become --set flags)
  • Polls /api/runs and progress.json every 1.5 s

Dev server

app/server.py (port 8766) reuses the handler of hud/server.py (the older dashboard on 8765). Python standard library only.

  • POST /api/launch starts run.py with JAX_PLATFORMS set from the Device choice; stdout goes to results/<run>/stdout.log
  • GET /api/run/<name>/<file> serves the run files, with an allow-list of names
  • /api/devices checks for a GPU

Solver process

run.py → pnpflow/runner.py. One process per run, inside the pnpflow conda env.

  • JAX assembly on the GPU when present; PARDISO sparse solve on the CPU
  • Writes only into its own results/<run>/
  • The Tauri desktop shell (app/src-tauri) is written but not compiled yet; it will replace the dev server
