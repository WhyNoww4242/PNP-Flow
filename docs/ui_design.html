Designing the pnpflow desktop app

The JAX solver works and is validated. The next step is a GUI that lets an electrochemist set up their own cell, electrode or channel without writing Python. This page shows a first proposal and asks the questions that decide the design. Answer them at the bottom, then export the answers and hand them back.

Solver
Python + JAX working
PNP + Stokes/Navier–Stokes, P2/P1 Taylor–Hood, exact Jacobians by jacfwd, adjoint sensitivities.
Validation
4 / 4 cases pass
Gouy–Chapman (err 3e-6), EO slit vs PB (2e-4), manufactured solution (2e-4), cylinder balances.

Proposed workflow

One path from a blank project to results. Each step writes a part of a single project file that the Python solver reads, so the GUI never needs to know any FEM.

Geometry
Template, sketch or import. Name the boundaries.
Electrolyte
Ions (z, D, cbulk), solvent ε, temperature.
Physics
PNP on/off flow, advection form, stabilisation.
Boundaries
Electrode, wall, inlet, outlet. Per-species conditions.
Mesh
Auto-refined to the Debye length, with quality check.
Study
Ramp parameters, sweeps, live convergence.
Results
Fields, profiles, currents, forces, sensitivities.

Rust: how the pieces fit

OptionWhat it isGood for usCosts
Tauri 2 suggested Rust backend, web front end in the system webview. Small installers. Reuses the HUD's WebGL field viewer, Plotly profiles and CSS. Impeccable's design tools work on it directly. Rust handles processes and files. Two languages in the GUI (Rust + JS/TS). Webview differences between Windows and Linux.
egui / eframe Immediate-mode, pure Rust, GPU via wgpu. One language. Very fast for large meshes. Good for dense tool-style panels. egui_plot for curves. The field viewer, colormaps and plots all need rewriting. Looks generic unless styled with care.
Slint Declarative UI language with a Rust API. Polished native widgets, live preview while designing. Custom GPU rendering for fields is harder. Smaller ecosystem for plots.
Iced Elm-style retained UI in Rust, wgpu. Clean state model, custom shaders possible. API still changing between releases. Fewer ready-made widgets for forms and tables.

Design process: impeccable

impeccable is a Claude Code skill: design playbooks plus a rule-based lint engine for HTML/CSS. Here is how it fits this project.

PieceWhat we do with it
Mode: OperateA solver GUI is a tool used for hours. Scanability, consistency and native behaviour come before expression. One type family, a fixed type scale, a restrained palette where the accent marks only actions, selection and state. Motion 150–250 ms and only to show state changes.
PRODUCT.mdWritten once by /impeccable init: users, purpose, operating context, constraints. Your answers below feed it.
DESIGN.mdDesign tokens (colours, type, spacing, components) that both the GUI and plots use. Field colormaps are cmasher (cosmic; iceburn for signed fields), never viridis or other matplotlib defaults, and are separate from UI colour.
shape → build → critique, auditPlan each screen before code, then review against Nielsen heuristics and accessibility (contrast at least 4.5:1, focus states, keyboard use).
detect lint + hookOnly scans HTML/CSS/JS. It works on a Tauri front end but not on egui, Slint or Iced code. With those we would use the playbooks by hand and critique screenshots.
Rules already applied hereSystem font instead of an overused web font. No numbered section labels, no uppercase kicker labels, no coloured side stripes, monospace only for numbers and code. Light and dark follow the OS.
