At a glance

pnpflow is a finite-element program for electrochemical systems: Poisson–Nernst–Planck ion transport, optionally coupled to fluid flow. The goal is that an electrochemist can model their own cell, electrode or pore without writing code. The solver is Python + JAX; the desktop app will be Rust (Tauri 2) with a web front end.

How it works

Three languages, each with one job

Desktop app (Rust + JavaScript)Window, menus, model tree, field viewer. Starts runs and watches them.
case / project →
← results/<run>/
run.py (Python)Builds the mesh, solves, analyses, writes result files.
calls
JAX coreWeak form, exact Jacobians by jacfwd, Newton, adjoint sensitivities.

The app and the solver only share files (docs/DATA_FORMAT.md), so an AI agent can drive the solver through the same files (docs/MCP.md). The .js files are JavaScript, the language of the app's web view, not Java.

What happens in one run

1 · Geometrygmsh (OCC) builds shapes and names every boundary.
2 · MeshCurved P2 triangles, refined where the physics is sharp.
3 · Mesh checkTwo views + diagnose, written before solving.
4 · Weak formOne JAX function per element; edges for natural BCs.
5 · Jacobianjax.jacfwd, exact, assembled sparse.
6 · NewtonPARDISO solves, line search, continuation; live progress.
7 · AnalysisFluxes, forces, profiles, adjoint dQ/dp, checks.
8 · OutputJSON for the app, figures, ParaView files.

Equations (dimensionless, steady)

species i :  div N_i = s_i,      N_i = c_i u − (d_i/Pe)(grad c_i + z_i c_i grad φ)
Poisson   :  −δ² lap φ = ρ/ρ_n + s_φ,      ρ = Σ z_i c_i
momentum  :  Re (u·grad) u = −grad p + lap u − K ρ grad φ     (optional)
mass      :  div u = 0                                          (optional)

Axisymmetric runs weight every integral by r. That is exact for Poisson and Nernst–Planck; flow in r–z needs extra terms, so the solver refuses that combination for now.

Example: uniformly charged sphere

matches the exact solution

A sphere of radius R = 1 with uniform charge density q = 1, in a domain of radius 10, solving only Poisson's equation, −lap φ = q inside and 0 outside. The model is axisymmetric: the solver works on the half plane r ≥ 0 and the figures mirror it to show the whole sphere. The outer boundary uses the exact far-field condition dφ/dn = −φ/R_out.

exact:  φ = qR²/2 − qρ²/6   (ρ ≤ R)        φ = qR³/(3ρ)   (ρ ≥ R),   ρ = √(r² + z²)

Halving the mesh size cuts the error about 7×, close to the h³ rate expected for quadratic elements.

Mesh check: two views + diagnose

all checks pass

Every run now draws its mesh twice before solving: the whole domain with boundaries coloured by name, and a zoom coloured by element quality. It also runs a diagnose pass and writes mesh/diagnose.json; every failure comes with a suggested fix.

Tested the other way too: a Gouy–Chapman mesh deliberately too coarse for its Debye length fails the double-layer check (2.2 elements, limit 8) with the fix "lower h_wall to ≤ δ/8". Known issue: for the sphere, view B zooms near the axis rather than the sphere surface, because the surface is an internal curve, not a named boundary.

Live status while solving

While it runs, the solver rewrites progress.json. The app reads it to draw the progress bar, the health badge and a live residual plot. Progress is never made up: when it cannot be measured it is null and the bar shows "unknown".

KeyMeaning
fraction0–1 through the continuation stages, from finished stages plus how far the residual has fallen in the current one
healthconverging struggling (short line-search steps, halvings) stalled (no drop in 3 steps) failed done
tellsthe numbers behind the verdict: residual, contraction ratio, line-search step, minimum concentration, halvings

Desktop app

first version

The layout follows your FreeCAD reference: menu bar, workbench tabs in the order the model is built (Geometry → Mesh → Materials → Boundaries → Equations → Study → Results), model tree with a property editor below it, document tabs and a status bar with live run state.

Reference

Design system and agent behaviour

  • impeccable design skill installed in the project (.claude/skills/impeccable). The app is an "Operate" tool: one UI font, a restrained palette where the blue accent marks only actions, selection and progress, and every control with all its states.
  • PRODUCT.md (who it's for, principles) and DESIGN.md (colours, type, components) carry the current HUD's colours and type, which you liked.
  • Figures use your house style: LaTeX/Times, 24 pt, 300 dpi, no boxes (only the x and y axis lines, each ending in an arrow), no colour-bar outline, panel labels a), b), and three cmasher maps only: cosmic (potential, concentrations), ember (|E|, |u|), bubblegum (charge density). Never viridis.
  • Standing agent behaviour for all your projects is in ~/.claude/CLAUDE.md: autodiff for every derivative, a validation case for every new term, live status, two-view mesh checks, figure style, impeccable rules, and checking pages by rendering them.
  • AGENTS.md explains this repo to any coding agent; docs/MCP.md specifies how an agent builds a gmsh geometry, checks the mesh and runs the solver.

How to run

From a Windows terminal (the solver runs in WSL):

cd C:\Users\Gnome\Desktop\VMBox\pnpflow
wsl -d Debian -- bash tools/wsl_run.sh python run.py charged_sphere --name sphere_demo
wsl -d Debian -- bash tools/wsl_run.sh python run.py --list           # all cases and parameters
wsl -d Debian -- bash tools/wsl_run.sh bash tools/validate.sh         # all validation cases

Results land in results\sphere_demo\: figures\ (PNG) and svg\, mesh\view_a.png, mesh\view_b.png, summary.json with every check.

To open the app (keep the terminal open while you use it):

wsl -d Debian -- bash tools/wsl_run.sh python app/server.py
then open in a browser:
  http://localhost:8766/                                          Start page
  http://localhost:8766/?run=sphere_demo&wb=results&view=field    the charged sphere
  http://localhost:8766/?new=charged_sphere                       new run from the template, F8 solves

New machines: conda env create -f environment.yml then conda activate pnpflow.
